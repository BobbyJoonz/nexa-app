# G-D1 — چک‌لیست QA دستگاه (۱۲ سناریوی ضدضربه)

> اجرا: مالک روی گوشی واقعی (همان گوشی دمو)، با APK بیلد #۱.
> هدف: معیار خروج «۱۲/۱۲ سبز بدون حتی یک کرش».
> هر سناریو: گام‌ها → انتظار دقیق → مدرک → طبقه‌بندی شکست.
> گزارش شکست به تلگرام: `https://t.me/imma_bobby` + اسکرین‌شات + «ساخت: <شناسهٔ بیلد>».

## ۰) قبل از شروع — ثبت شناسهٔ بیلد

| فیلد | مقدار | منبع |
|---|---|---|
| نسخهٔ اپ | `apps/mobile/package.json → version` (1.1.0) | فایل |
| versionCode | `apps/mobile/app.json → expo.android.versionCode` (2) | فایل |
| کامیت | `git log -1 --oneline` | ترمینال |
| دستگاه | برند/مدل/اندروید نسخه | تنظیمات گوشی |
| زمان شروع/پایان | | |

این ۵ مقدار در ابتدای گزارش و در هر شکست تکرار می‌شود.

## سناریوها

### S1 — لانچ، لودر، انتخاب زبان
- گام: اپ را باز کن. لودر برند را ببین، بعد صفحهٔ زبان.
- انتظار: لودر با لوگو NEXA؛ **اولین لانچ (سرد) روی دستگاه ارزان ≤ ۵ ثانیه، لانچ‌های بعدی ≤ ۲٫۵ ثانیه** (این انتظار واقع‌بینانه است؛ نگران نشو اگر لانچ اول کمی بیشتر طول کشید — فقط اگر > ۸ ثانیه باشد گزارش کن)؛ صفحهٔ «دانش فنی، بدون پیچیدگی.» با دو دکمه.
- مدرک: اسکرین‌شات لودر + صفحهٔ زبان.
- شکست: لوگو نمی‌آید / متن فارسی به‌هم‌ریخته / لانچ اول > ۸ ثانیه → گزارش.
- طبقه‌بندی شکست: JS (فونت/تایمینگ) | نیتیو (اسپلش).

### S2 — آکادمی + ثبت مرور + پایداری بعد از kill
- گام: زبان fa → مدل CM3500-24S → آکادمی. یک درس غیربحرانی را باز کن → «به‌عنوان مرورشده ثبت کن» → برگرد. اپ را از Recent بکش (kill). دوباره باز کن → آکادمی.
- انتظار: نوار پیشرفت `%` بالا رفته باشد و «بخش مرورشده» علامت ✓ داشته باشد — **یعنی AsyncStorage واقعاً ذخیره کرده**.
- مدرک: ۲ اسکرین‌شات (قبل/بعد از kill) با درصد متفاوت.
- شکست: درصد برگشته به ۰ → باگ persistence (منتقد: JS/نیتیو AsyncStorage).
- طبقه‌بندی: JS | نیتیو.

### S3 — شبیه‌ساز LCD (سه‌حالته)
- گام: درس «شبیه‌ساز LCD» → حالت browse: چند برنامه را با ▼/▲ بچرخان (حتماً ۰۱ تا ۳۱). یکی را edit کن → مقدار عوض کن → ENTER. ESC را بزن.
- انتظار: منوی دقیقاً ۳۱ برنامه با شماره/نام دفترچه؛ ویرایش در حافظهٔ نشست؛ ESC خروج تمیز؛ **برنامه‌های range فقط مقدار پیش‌فرض و پنل «روی دستگاه با گام تنظیم می‌شود» را نشان بدهند**؛ پنل آموزشی زیر برنامه دیده شود.
- مدرک: ۳ اسکرین‌شات (browse/edit/پنل آموزشی).
- شکست: تعداد برنامه ≠ ۳۱ | ویرایش ذخیرهٔ دائمی کرد (نباید) | کلیدهای لمسی جواب ندادند → گزارش.
- طبقه‌بندی: JS (بیشتر) | نیتیو (لمس).

### S4 — کوییز منبع‌دار
- گام: درس کوییز → یک پاسخ اشتباه → پاسخ درست → بازخورد + ردیف منبع → دکمهٔ «شروع دوباره».
- انتظار: دابل‌تپ محافظت شده (دومین تپ بی‌اثر تا جواب اول ثبت شود)؛ ردیف منبع «دفترچه ص X» دیده شود؛ شروع دوباره سؤال‌ها را برنگرداند.
- مدرک: اسکرین‌شات بازخورد + منبع.
- شکست: کرش روی تپِ سریع (دابل‌تپ) | منبع خالی → گزارش.
- طبقه‌بندی: JS.

### S5 — جست‌وجو با اعداد مضبوط فارسی
- گام: از صفحهٔ اصلی → جست‌وجو. «۰۱» بنویس؛ پاک کن؛ «١» بنویس؛ پاک کن؛ «1» بنویس؛ یک کد خطا مثل «E06» یا «F01» بزن.
- انتظار: هر سه شکل عددی همان برنامه/کد را بدهند (عادی‌سازی ارقام ۰-۹ + ٠-٩)؛ کارت کد خطا عنوان + اقدام ایمن + منبع را نشان دهد.
- مدرک: اسکرین‌شات یکی از نتایج یکسان (۳ شکل).
- شکست: «۰۱» و «1» نتایج متفاوت → باگ normalize (منتقد: `search.tsx normalizeKey`).
- طبقه‌بندی: JS.

### S6 — چک‌لیست kill-and-reopen
- گام: چک‌لیست راه‌اندازی → ۲ گام تیک → اپ را kill → باز کن → چک‌لیست.
- انتظار: تیک‌ها باقی بمانند؛ درصد و متن «X از ۸ گام» درست؛ دکمهٔ «پاک‌کردن تمام تیک‌ها» بعد از تیک‌زدن همه، همه را بردارد.
- مدرک: ۲ اسکرین‌شات قبل/بعد kill.
- شکست: تیک‌ها ناپدید شدند → باگ persistence دوم (باید هر دو S2 و S6 سبز باشند).
- طبقه‌بندی: JS | نیتیو.

### S7 — ماشین‌حساب با اعداد منبع (غیرقابل‌بحث)
اعداد تقلبی نمی‌شود؛ این موارد را عیناً وارد کن و نتیجه را مطابق جدول چک کن:

| سناریو | ورودی | انتظار |
|---|---|---|
| واتمنتا OK | 8×41V، −0.30%/°C، −10°C، 1 رشته، 11A، 450W، بار 2500W، شارژ 30+60 | ✓ همه pass؛ Voc ≈ 362.4 < 500؛ توان 3600 ≤ 4000؛ جریان 11 ≤ 15 |
| ولتاژ FAIL | همان ولی 12 پنل سری | Voc ≈ 543.7 > 500 → **fail + قرمز** |
| جریان FAIL | 2 رشته × 11A | 22 > 15 → **fail** |
| توان FAIL | 8×550W | 4400 > 4000 → **fail** |
| بار مرزی | بار 3500W | به‌دقت **marginal** (نه pass) |
| شارژ FAIL (جمع) | 40 + 70 | جمع 110 > 100 → **fail** |
| شارژ FAIL (برق شهر تنهایی) | 65 + 0 | utility 65 > 60 → **fail**؛ total **skipped** (چون PV صفر است) |
| فرم خالی | همهٔ فیلدهای شارژ خالی | **skipped**، هرگز pass |

> اعداد با تست‌های قفل‌شدهٔ موتور یک‌به‌یک‌اند (`tests/sizing.test.ts`): 8×41V، β=-0.3%/°C، −10°C → 362.44V. اگر اپ عدد دیگری داد، باگ است، نه اختلاف نظر.

- گام: حداقل ۳ ردیف اول را اجرا کن (ترجیحاً همه).
- مدرک: اسکرین‌شات هر حالت (fail باید قرمز باشد، skipped باید «—» باشد).
- شکست: «فرم خالی = pass» یا هر dev از جدول → باگ موتور (این تست‌ها قبلاً سبزند؛ روی دستگاه باید همان‌طور باشد).
- طبقه‌بندی: JS.

### S8 — کانال بازخورد تلگرام
- گام: در هر صفحه‌ای نوار «خطای محتوایی دیدید؟» → تلگرام.
- انتظار: برنامهٔ تلگرام (یا مرورگر) با `t.me/imma_bobby` باز شود؛ نوار ایمیل **وجود نداشته باشد** (خفته).
- مدرک: اسکرین‌شات.
- شکست: باز نشد / ایمیل هم نشان داده شد (باید فقط تلگرام باشد).
- طبقه‌بندی: JS.

### S9+S10 — تمام مسیرهای بازگشت
- گام: از آکادمی تا عمیق‌ترین صفحه (کوییز/LCD) برو و با **دکمهٔ بازگشت سیستمی** (ژست اندروید) همه‌جا برگرد؛ سپس همین کار با دکمهٔ back هدر.
- انتظار: هیچ جا گیر نکند؛ از شبیه‌ساز LCD بازگشت = برگشت به منوی درس (نه خروج از اپ)؛ صفحهٔ قبلی با وضعیتش (اسکرول/تیک‌ها) برگردد؛ از صفحهٔ اول، back = خروج از اپ (یا home).
- مدرک: هیچ — مشاهده‌ای؛ در پایان، logcat را چک کن که `FATAL` نباشد.
- شکست: گیرکردن/کرش روی back (به‌خصوص از شبیه‌ساز LCD و کوییز) → گزارش فوری.
- طبقه‌بندی: JS (نویگیشن).

### S11 — ۳۰ دقیقه بی‌کرش (پایداری)
- گام: اپ را باز بگذار؛ هر ~۵ دقیقه یک کار واقعی (جست‌وجو، LCD، کوییز، چک‌لیست). ۵ دقیقه هم بی‌کار بگذار ببین زنده می‌ماند. صفحه را خاموش کن و بعد بیدارش کن (DOZE).
- انتظار: صفر `FATAL` در پایان. بعد از بیداری: اگر اپ زنده بود وضعیت یکسان؛ **اگر توسط مدیر باتری OEM کشته شد (شناخته‌شده در MIUI/HyperOS، ColorOS، OnePlus)**، باز شدن دوباره + برگشتِ وضعیت ذخیره‌شده (تیک‌ها/درصد) همان قبول است — این همان آزمون persistence است، نه شکست.
- مدرک: در پایان: `adb logcat -d | Select-String "FATAL EXCEPTION"` → خالی.
- شکست: کرش واقعی (`FATAL` در logcat) یا ازبین‌رفتن وضعیت ذخیره‌شده بعد از بازگشایی = پریوریتی ۱ (همه‌چیز را نگه دار: logcat کامل + زمان).
- طبقه‌بندی: هر FATAL = پریوریتی ۱.

### S12 — حالت‌های خالی و لبه‌ها
- گام: (الف) جست‌وجوی بدون نتیجه («zzz») → پیام «چیزی پیدا نشد». (ب) چک‌لیست با ۰ تیک → درصد ۰٪ و متن درست. (ج) بازنشانی همهٔ مرورها → آکادمی ۰٪. (د) deep-link خراب — با adb (دستور زیر) یا از هر QR/نوت: یک لینک به آکادمیِ مدل ناموجود بزن → **صفحهٔ «این مدل پیدا نشد» با دکمهٔ back** (نه صفحهٔ سفید!). (هـ) **آفلاین:** هواپیما را روشن کن ← اپ را باز کن → همهٔ بخش‌ها (از جمله PDF ها) کار کنند.
  ```powershell
  adb shell am start -a android.intent.action.VIEW -d "nexaacademy://academy/doesnotexist"
  ```
- انتظار: هیچ صفحهٔ سفید یا کرشی؛ آفلاین بدون هیچ وابستگی شبکه (این دقیقاً ادعای دموی توست: بدون اکانت، بدون اتصال).
- مدرک: اسکرین‌شات «پیدا نشد» + حالت آفلاین.
- شکست: صفحهٔ سفید روی deep-link بد → باگ (در بیلد #۱ باید رفع‌شده باشد)؛ هرچیزی که آفلاین بشکند → گزارش.
- طبقه‌بندی: JS.

## ۱) ملاحظات محیط (قبل از اجرا بخوان — این‌ها باگ نیستند)
1. **adb روی این ویندوز نیست (winget هم نیست):** دانلود دستی Platform-tools از developer.android.com/tools — ⚠️ **با VPN** (dl.google.com + developer.android.com هم مثل exp.host فیلترند؛ در آزمایشِ همین سند، دانلود مستقیم صفحهٔ خطا برگرداند) → Extract به `C:\platform-tools` → `setx PATH "$env:PATH;C:\platform-tools"` (ترمینال جدید). قبل از S11/S12 لازم است.
2. **باز کردن PDF ها:** اپ از اشتراک‌گذاری سیستم استفاده می‌کند؛ اگر گوشی اپ PDF نداشته باشد (مثل Google Files)، دکمه هیچ کاری نشان نمی‌دهد — یک بینندهٔ PDF نصب کن. باگ اپ نیست.
3. **مدیران باتری OEM** می‌توانند اپ را در پس‌زمینه بکشند (S11 را ببین) — برای قفل‌کردن در حافظه: تنظیمات → باتری → بدون محدودیت برای این اپ (اختیاری).

## ۳) اگر چیزی شکست خورد (پروتکل)
1. اسکرین‌شات + شمارهٔ سناریو + شناسهٔ بیلد → تلگرام.
2. اگر logcat داری: `adb logcat -d > crash.txt` و بفرست.
3. من طبقه‌بندی می‌کنم: **JS** (فیکس + OTA بعد از فعال‌شدن، یا APK بعدی) | **نیتیو** (بیلد جدید حتمی) | **محتوا** (دادهٔ product-content).
4. بعد از فیکس: همان سناریو + «دود مجدد» = **کل S1–S12 دوباره**، چون هر فیکس می‌تواند جابه‌جا بشکند.
